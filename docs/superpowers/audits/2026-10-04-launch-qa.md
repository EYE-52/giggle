# Giggle prelaunch UI and functional QA

**Date:** 4 October 2026, Asia/Kolkata  
**Baseline:** `9e6bf4a` on `main`  
**Scope:** Web app. Local accounts and two browser origins were used for mutations; the owner's existing production account was used for a normal Google logout and login. Native apps were not exercised.

The main web screens have been polished within the existing five themes. The functional checks below passed, but this is not a claim that every feature or physical call is launch-ready. A two-device camera and microphone check remains necessary.

## Changes in this release

- Home uses balanced columns, original Giggle characters in the empty friends state, squad cover stamps using the shared logo, and fewer outlined utility controls.
- Discover has a visible title, a direct Create a squad action, clearer filtering, and more consistent card spacing. An approved join request now enters its lobby instead of leaving the applicant on Request sent.
- Profile settings use the shared theme surfaces. Scrapbook settings stay on notebook paper instead of inheriting sticky-note colors. Its identity card and preview still use sticky notes.
- Friends has a more deliberate illustrated first-run state. Accepting a request through notifications refreshes the list immediately; existing refresh/mutation race guards remain intact.
- Notification actions paint above transformed page content, fixing search inputs intercepting Accept clicks.
- Chat supports escaped, clickable HTTP/HTTPS links. Credential-bearing URLs, unsupported protocols, and markup remain plain text. Emoji choices no longer push the composer out of short screens.
- Encounter mic/camera states derive from actual capture events. Updates are serialized, stale completions are ignored, and controls cannot pretend to switch a disconnected device on.
- Sign-in explains the actual steps using plain copy. The local development badge is hidden because it covered phone Home and emoji hit targets; compile/runtime errors still surface.

## Follow-up: earned Giggle+, characters, topics and onboarding

Baseline for this follow-up: `1fcc155` on `main`. The earlier table describes the first UI release; the checks here describe the subsequent changes.

- The web Wallet hides all payments, subscription pricing and cosmetic sales. Referrals earn 100 credits per converted new account; leading a first squad earns 25 once. A seven-day Plus pass costs 200 earned credits and gives eight-person squads and a profile badge. Credits, expiry and redemption are authoritative on the server.
- The character editor has original bucket hats, cat-eye glasses, sunglasses, drop earrings, necklaces and headphones, with accessory colors and a clearer responsive layout. The pendant and shirt use the same shared Giggle mark. Saved version-1 characters retain defaults for new fields.
- Topics are available when creating a squad and from the lobby header. Home/Discover show actual popular-topic counts across open squads. Keyword moderation rejects known NSFW/hate terms and common fullwidth/diacritic/spacing/leet obfuscation; benign topics including Music production, Spicy food and Grape juice remain accepted. It is not comprehensive language or evasion detection.
- Remote listening preferences survive unpublishing and reconnecting within a call, and clear on leaving it. Participant names truncate without hiding microphone/listening state; touch devices expose the person-menu hint. Missing devices get plain recovery instructions rather than raw SDK errors or an enabled-looking camera.
- Invite codes persist through landing, sign-in, policy links and Back. The age form fits 320px screens and handles invalid dates. The identity-only account screen explains underage restrictions without claiming provider verification. Public entry copy reflects temporary self-declared age access honestly.
- Shared-browser account switching isolates device-only avatars and cached credits/entitlements. Each account's local picks survive switching back; theme preferences remain shared.
